## 強制前置動作

### Step 1 — 掃描現有文章庫
```
glob: src/content/blog/**/*.{md,mdx}
```
讀取每篇的 frontmatter，統計：
- 各分類（①②③④）現有篇數 vs 目標篇數
- 已覆蓋的主題關鍵詞
- draft: true 的草稿數量

### Step 2 — 生成現況快照
輸出格式：

```
## 內容庫現況

| 分類 | 目標 | 現有 | 缺口 |
|---|---|---|---|
| ①身體訊號解讀 | 10 | X | X |
| ②慢性發炎科學 | 12 | X | X |
| ③精準健康工具 | 16 | X | X |
| ④介入與調校  | 7  | X | X |

已覆蓋主題：...
明顯缺口：...
```

## 漏斗邏輯

```
① 身體訊號解讀（上漏斗）
   └── 目標：讓陌生人意識到「我的身體有問題」
   └── TA 痛點：疲勞、睡眠差、記憶力下降、體重難控
   └── CTA：軟退出 → LINE 領清單

② 慢性發炎科學（中漏斗）
   └── 目標：讓讀者理解機制，建立科學信任感
   └── TA 痛點：想知道為什麼、看過數據但不懂意義
   └── CTA：軟退出 → LINE 領清單

③ 精準健康工具（中下漏斗）
   └── 目標：讓讀者想量化自己的狀態
   └── TA 痛點：「我要怎麼知道自己的狀況？」
   └── CTA：硬退出 → 預約 Prysm iO 掃描

④ 介入與調校（下漏斗）
   └── 目標：讓已理解問題的人採取行動
   └── TA 痛點：「知道有問題，但不知道怎麼解」
   └── CTA：硬退出 → 諮詢 / 產品
```

## 主題提案格式

當使用者要求「提案新文章主題」時，每個提案包含：

```markdown
### 主題：[標題]

- 分類：①②③④
- 痛點切入：讀者在想什麼 / 困擾是什麼
- 科學鉤子：哪個研究/機制可以作為核心
- 建議 Hook 第一句：（直接寫出來）
- 預計 CTA：軟/硬退出
- 與現有文章的連結：可從哪篇導入 / 可導出到哪篇
```

一次提案 3–5 個，讓使用者選擇。

## 系列文章規劃原則（Rule 23）

系列文章之間必須有「前情提要鉤」：
```
上篇結論一句話 + 新問題拋出
→ 讓沒讀過的人也能進入
→ 讓讀過的人想追下去
```

規劃系列時輸出：
```
系列名稱：
篇數：X 篇
各篇主題 + 分類 + 連結邏輯：
建議發佈順序：
```

## TA 定位（全域限制）

- 核心定位：「把健康排最後的你」
- 禁止：「科技人」「菁英」「百萬年薪」「高收入族群」
- 語氣：像一個懂科學的朋友，不像白袍醫師，也不像業務
