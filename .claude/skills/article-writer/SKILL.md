## 強制前置動作（每次必跑，不可跳過）

### Step 1 — 載入寫作規則
讀取專案根目錄的 `WRITING-RULES.md` 全文。
這 23 條規則是所有內容的基礎規範，後續每個步驟都以此為準。

### Step 1b — 載入圖片規範
讀取專案根目錄的 `IMAGE-STYLE.md`。
文章中的每張配圖（封面＋2～4 張內文圖）都依該文件第 10 節的格式輸出提示語。

### Step 2 — 掃描現有文章庫
```
glob: src/content/blog/**/*.{md,mdx}
```
列出現有文章的 slug 與 title，確認：
- 同主題是否已存在 → 若存在，詢問「更新現有文章」還是「撰寫獨立新篇」
- 漏斗各分類目前篇數是否達標（參照 CLAUDE.md 目標篇數）

### Step 3 — 確認任務參數
若使用者未主動說明，依序詢問（一次問完，不要分開問）：

1. 文章主題 / 關鍵科學概念是什麼？
2. 屬於哪個漏斗分類？（①②③④）
3. 有指定參考文獻或 DOI 嗎？
4. 目標平台（部落格 / FB / Threads / 電子報）？

## 文章結構（必須遵守）

```
Hook → Premise → Emotion → Data+Image → CTA
```

對應 WRITING-RULES.md 執行架構：

| 區塊 | 對應規則 | 執行要點 |
|---|---|---|
| Hook | Rule 1, 10, 11 | 第一句 1 秒內讓人停；直接開始，留資訊缺口 |
| Premise | Rule 2, 3, 7 | 先提前提，讓產品/解法成為邏輯必然 |
| Emotion | Rule 3, 15 | 情緒先行；命中讀者目前困境「這在說我」 |
| Data+Image | Rule 16, 17, 21, 22 | 數據後接畫面感；四字醫學詞後接「也就是說…」 |
| CTA | Rule 4, 9, 20 | 依漏斗分類設定 ctaType；用 ctaBridge 說清楚下一步，內文不另寫 CTA |

## CTA 決策規則

CTA 由版面（`src/layouts/BlogPost.astro`）自動加在每篇文末，**內文不要再自己寫 CTA**（不放 LINE 連結、不放「加我 LINE」「傳給我」「填資料表」等句子），否則會和版面 CTA 重複。

```
文章分類 ①② → ctaType: 'soft'（可省略，預設 soft）
  └── 版面按鈕：1 分鐘身體警報評估（/assessment），次要連結 /prescan

文章分類 ③④ → ctaType: 'hard'（必填）
  └── 版面按鈕：填寫資料表（/prescan），次要連結 /assessment
```

想針對這篇客製引導語，寫在 frontmatter 的 `ctaBridge`（一到兩句，說清楚「下一步具體要做什麼」，符合 Rule 20）。

## Frontmatter 規範

欄位以 `src/content.config.ts` 為準：

```yaml
---
title: '標題（繁體中文，含關鍵詞）'
description: 'SEO 描述，120 字以內'
pubDate: YYYY-MM-DD
heroImage: './cover.webp'
category: '身材'           # 六選一：身材｜臉蛋｜性健康｜禿頭、白髮｜心血管｜健檢站（男性慢老六站）
product: true              # 只有產品介紹文章才加；性健康站不能放產品文章
tags: ['標籤1', '標籤2']
slug: 'kebab-case-english-only'
ctaType: 'hard'            # ③④ 必填；①② 可省略
ctaBridge: '客製引導語（選填）'
---
```

**資料夾＝漏斗層級（決定網址前綴與 CTA，讀者看不到）：** 上漏斗放 `body-signals/`、中漏斗 `chronic-inflammation/`、中下漏斗 `precision-health-tools/`、下漏斗 `intervention-optimization/`。

**slug 規則：**
- 全英文，kebab-case
- 禁止中文字元（會導致 Cloudflare Pages 路由問題）
- 範例：`chronic-inflammation-mitochondria-aging`

## 引用規範

- 每個科學數據必須附 DOI 或 PubMed PMID
- **例外：以下來源沒有 DOI，可以附官方網址引用**
  - 政府統計與公告：衛福部、國健署、健保署、疾管署等官方網站（引用官方原始頁面，不引用轉述的新聞報導）
  - 廠商官方技術文件：裝置或軟體的官方說明、開發者文件（例如 Apple HealthKit 文件），只能用來說明「這個產品怎麼量、怎麼算」，不能當作健康效益的證據
  - 國內醫學會或醫師公會的期刊文章（例如《台灣醫界》）：附期刊名、卷期、頁碼與網址
  - 技術部落格（例如 iThome 鐵人賽）：只能用於技術說明，引用時標註「非同儕審查」，不能單獨支撐健康結論
- 例外來源格式：`作者或機關。標題。出處，年份。網址`
- 格式：`（來源：[期刊名稱](https://doi.org/xxxxx)，YYYY）`
- 禁止引用無法驗證的資料

## 交稿前必查清單（每篇必跑，逐項確認後才能交稿）

這份清單來自 2026-10 全站 68 篇檢查時反覆出現的錯誤。交稿時在回覆最後列出每一項的檢查結果（✅／已修正／不適用）。

### A. 前台看得到的錯誤
- [ ] 所有站內連結都是 `/blog/<分類資料夾>/<slug>/`，而且那篇真的存在（用 glob 確認 slug），沒有 `(#)`、`/SLUG-`、電腦檔案路徑
- [ ] 圖片語法是 `![說明](./檔名.webp)`，alt 裡沒有產圖提示語、編輯備註
- [ ] 沒有「上稿前刪除」「編輯備注」「版本 A／B」等草稿殘留；粗體、表格、標題（`## ` 後有空格）語法正確
- [ ] 「上一篇」「下一篇」「前幾篇」「B 篇」都換成真正的文章標題加連結
- [ ] 參考文獻每一筆都和本文主題相關，作者、年份、期刊齊全；沒有錯貼的文獻

### B. 法規（台灣食品廣告）
- [ ] 產品（食品／保健品）沒有宣稱：治療或預防疾病、改善睡眠、提升睪固酮、改善性功能、減少腰圍或體脂肪、經前症候群、延緩老化、讓生理年齡變年輕
- [ ] 成分研究和產品分開寫：寫明「以下是成分研究，不代表產品效果」；動物研究標明是動物研究
- [ ] 原廠自己做的研究，註明「原廠研究」；只公布補充組百分比、沒有安慰劑組的數字，不引用
- [ ] 不寫「全球第一」「最強」「最有效」「唯一」，除非有可查證的出處

### C. 安全與就醫
- [ ] 談到症狀（疲勞、失眠、打鼾、記憶力、情緒、聽力、掉髮、血壓、血糖），寫出「什麼情況要先看醫生、看哪一科」
- [ ] 談憂鬱或情緒低落，附衛福部安心專線 1925
- [ ] 提到補充品劑量時，寫「依產品標示」，並提醒抗凝血藥、降血糖藥、降血壓藥、懷孕哺乳等族群先問醫師或藥師
- [ ] 提到處方藥（GLP-1、睪固酮補充、安眠藥等），寫明需經醫師評估，不要叫讀者自行停藥或替換
- [ ] 沒有任何句子暗示「不用看醫生」

### D. Prysm iO 的說法（全站統一口徑）
- [ ] 只說它「反映過去幾週蔬果與類胡蘿蔔素的攝取狀態，適合看趨勢」
- [ ] 不說它能量：老化速度、生物年齡、端粒、NAD+、粒線體、大腦或神經保護儲備、根本原因、細胞防禦力
- [ ] 不寫「實驗室等級」「終極裁判」「媲美醫療級」；R² 約 0.77 要說明仍有誤差
- [ ] 單次掃描測量次數用原廠 2026 更新的「700,000+ 次」；Riggs 2026 研究要註明作者群包含 Nu Skin 研究人員

### E. 數字與跨篇一致（以下為全站統一說法，不要寫出不同版本）
- [ ] 壽命遺傳度：2026《Science》雙胞胎研究，排除意外與傳染病後「約一半（約 50%）」，講的是壽命，不是老化速度
- [ ] 老化加速期：44 歲與 60 歲（Stanford 2024, *Nature Aging*）
- [ ] hs-CRP：<1 低、1–3 中、>3 mg/L 高（AHA）；一般 CRP 參考值多為 <0.5 mg/dL（＝5 mg/L），注意單位
- [ ] 睪固酮與睡眠：寫「需要完整、不被切碎的睡眠」，不綁定深眠或 REM 單一階段
- [ ] McCay 1935 大鼠實驗：寫「明顯延長」，不寫「將近一倍」或具體百分比
- [ ] ageLOC R2：依原廠說法「日錠支持白天的能量代謝，夜錠支持夜間的淨化與修復」，不自己對應 Nrf2／SIRT1 等路徑
- [ ] GRAS 是「公認安全」制度，不是 FDA「認證」；GMP 要分清楚食品 GMP 和藥品 PIC/S GMP
- [ ] 類淋巴系統（睡眠時大腦清洗）：要提到 2024 年 Miao 等人的相反結果，語氣寫「仍有爭議」
- [ ] 百分比換算、倍數、年份都對照原文；看不到原文的數字不用

### F. CTA 與結構
- [ ] 內文沒有自己寫的 CTA；③④ 類有 `ctaType: 'hard'`
- [ ] 不提 lead magnet 名稱；若必須提，只用【身體警報訊號自我評估清單】
- [ ] ①② 上中層文章不在內文直接推產品，延伸閱讀優先放知識型文章
- [ ] 同一個段落沒有在別篇整段出現過（先 grep 關鍵句）；同一篇內沒有重複段落
- [ ] 篇幅：一篇一個核心想法，超過 2,500 字先檢查是否塞了兩個主題
- [ ] 跑過 `speak-human-agelocked` 去 AI 味（「不是A而是B」每篇最多 1 次）
