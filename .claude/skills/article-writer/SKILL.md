# SKILL: agelocked-article-writer

適用任務：撰寫新文章、修改現有文章、起草草稿、重寫段落

---

## 強制前置動作（每次必跑，不可跳過）

### Step 1 — 載入寫作規則
讀取專案根目錄的 `WRITING-RULES.md` 全文。
這 23 條規則是所有內容的基礎規範，後續每個步驟都以此為準。

### Step 2 — 掃描現有文章庫
```
glob: src/content/blog/**/*.{md,mdx}
```
列出現有文章的 slug 與 title，確認：
- 同主題是否已存在 → 若存在，詢問「更新現有文章」還是「撰寫獨立新篇」
- 漏斗各分類目前篇數是否達標（參照 CLAUDE.md 目標篇數）

### Step 3 — 確認任務參數
若使用者未主動說明，依序詢問（一次問完，不要分開問）：

1. 文章主題 / 關鍵科學概念是什麼？
2. 屬於哪個漏斗分類？（①②③④）
3. 有指定參考文獻或 DOI 嗎？
4. 目標平台（部落格 / FB / Threads / 電子報）？

## 文章結構（必須遵守）

```
Hook → Premise → Emotion → Data+Image → CTA
```

對應 WRITING-RULES.md 執行架構：

| 區塊 | 對應規則 | 執行要點 |
|---|---|---|
| Hook | Rule 1, 10, 11 | 第一句 1 秒內讓人停；直接開始，留資訊缺口 |
| Premise | Rule 2, 3, 7 | 先提前提，讓產品/解法成為邏輯必然 |
| Emotion | Rule 3, 15 | 情緒先行；命中讀者目前困境「這在說我」 |
| Data+Image | Rule 16, 17, 21, 22 | 數據後接畫面感；四字醫學詞後接「也就是說…」 |
| CTA | Rule 4, 9, 20 | 依漏斗分類決定軟/硬退出；說清楚加 LINE 後的第一步 |

## CTA 決策規則

```
文章分類 ①② → 軟退出
  └── 文字：「想知道你現在的身體警報等級？」
  └── 行動：加入 LINE @fer7932k，領取【身體警報訊號自我評估清單】

文章分類 ③④ → 硬退出
  └── 文字：「準備好用數字看懂自己的身體了嗎？」
  └── 行動：預約 Prysm iO 類胡蘿蔔素掃描 / 直接諮詢
```

## Frontmatter 規範

```yaml
---
title: "標題（繁體中文，含關鍵詞）"
description: "SEO 描述，120 字以內"
pubDate: YYYY-MM-DD
slug: "kebab-case-english-only"
category: "①身體訊號解讀 | ②慢性發炎科學 | ③精準健康工具 | ④介入與調校"
tags: ["標籤1", "標籤2"]
draft: false
---
```

**slug 規則：**
- 全英文，kebab-case
- 禁止中文字元（會導致 Cloudflare Pages 路由問題）
- 範例：`chronic-inflammation-mitochondria-aging`

## 引用規範

- 每個科學數據必須附 DOI 或 PubMed PMID
- 格式：`（來源：[期刊名稱](https://doi.org/xxxxx)，YYYY）`
- 禁止引用無法驗證的資料

## 繁中寫作細節（Rule 22 展開）

每出現四字醫學名詞必接白話翻譯：
```
❌ 代謝彈性下降時，粒線體效率同步降低。
✅ 代謝彈性（也就是你的身體在燃燒脂肪和糖分之間切換的能力）下降時，
   粒線體效率同步降低。
```

---

## 禁止事項

- 禁止「科技人」「菁英」「百萬年薪」等舊版 TA 語言
- 禁止單篇出現多個不同 CTA 方向
- 禁止省略 DOI
- 禁止 slug 含中文
- 禁止壓縮長文（Rule 13：從長文中選一個概念，不是縮寫全文）

---

## 輸出格式

輸出完整 `.md` 檔案內容，包含：
1. 完整 frontmatter
2. 文章本文
3. 結尾 CTA 區塊

不要只輸出摘要或大綱——直接輸出可貼入 `src/content/blog/` 的完整檔案。
